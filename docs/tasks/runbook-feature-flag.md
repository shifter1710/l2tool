# Задача (задел): ранбук за фича-тоглом

Статус: ранбук «куда смотреть» спрятан за тоглом `[features] runbook` в
config.toml, по умолчанию выключен (`core.config.feature_enabled`).
Хранилище `runbook.json`, его бэкапы и перенос в бандле «все конфиги»
работают независимо от тогла — включение в любой момент возвращает панель
с прежними кейсами.

## Что осталось до включения по умолчанию

Известный баг (найден при проверке релиза v1.3.1): после разбора заявки
без перезагрузки страницы (AJAX) запуск кейса ранбука показывает
«Сначала разберите заявку», хотя заявка только что разобрана.

Причина: форма кейса на главной (`templates/index.html`, скрытая
textarea `effective_ticket_text`) рендерится серверно один раз, а
`static/app.js` при AJAX-разборе заменяет только `#result-zone` и поле
не синхронизирует; `POST /runbook` (`webapp.py`) берёт текст заявки
только из этой формы. Поле `window` формы кейса тоже устаревает.

Вариант решения: после успешного `submitViaFetch('/analyze')` обновлять
`effective_ticket_text` (и `product`/`window`) во всех
`form[action="/runbook"]` из ответа — в частичном ответе `_results.html`
эффективный текст уже есть в форме вторичной диагностики; для продуктов
без UUID-уровня потребуется отдельный скрытый носитель текста в
частичном ответе. JS-тестов в репозитории нет — проверять вручную:
разобрать заявку → нажать кейс → в шагах должны быть ссылки.

## Чек-лист включения

1. Починить синхронизацию (выше), проверить вручную.
2. Включить `runbook = true` в `config.example.toml`, убрать гейт
   по согласованию.
3. Обновить README (раздел «Настройка») и таблицу маршрутов в
   `docs/ARCHITECTURE.md` (пометка «фича-тогл»).
4. Полный прогон `pytest` + `ruff`, ручной сценарий из CONTRIBUTING.
