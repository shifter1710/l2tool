# Задачи: редизайн веб-интерфейса

Самодостаточный план для работы в отдельных чатах. Полный аудит и
обоснование — в [docs/UI_PLAN.md](../UI_PLAN.md); этот файл — рабочий
список задач. Ветка: `feature/ui-redesign` (создана от `dev`).

## Как работать с задачей (для нового чата)

1. Переключиться: `git checkout feature/ui-redesign` (или создать подветку
   `feature/ui-phase-N` от неё, если параллелите работу).
2. Прочитать: эту задачу, раздел «Ограничения» ниже и соответствующие файлы.
3. Сделать задачу целиком, прогнать проверки (см. «Проверка»).
4. Коммит в `feature/ui-redesign`, push, PR в `dev` (или merge, если PR
   недоступен). Скриншоты светлой и тёмной темы — в описание PR.

## Контекст: что где лежит

- `templates/index.html` — главная: форма заявки, результаты, вторичная
  диагностика, пакетная загрузка.
- `templates/settings.html` — конструктор диагностических блоков.
- `static/styles.css` — все стили (437 строк), light/dark через
  `:root[data-theme="dark"]`, есть захардкоженные hex-цвета статусов.
- `static/app.js` — тема, копирование ссылок, подтверждение удаления (107 строк).
- `webapp.py` — роуты и контекст шаблонов; CSP задаётся в middleware
  `secure_local_responses`.
- Ссылки на стили кэшбастятся вручную: `?v=YYYYMMDD-N` — при любом изменении
  CSS/JS поднять версию в обоих шаблонах.

## Ограничения (нарушать нельзя)

- CSP: `script-src 'self'; style-src 'self'` — никаких CDN, внешних шрифтов,
  инлайн-скриптов/стилей. Инлайн-SVG в HTML разрешён.
- Всё должно работать с отключённым JavaScript (формы — обычные POST).
- Никаких внешних запросов; только localhost.
- Фреймворки и сборщики не вводим.

## Проверка (после каждой задачи)

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check .
.venv/bin/python webapp.py --no-browser   # ручная проверка на 127.0.0.1:8765
```

Ручной чек-лист: светлая и тёмная темы, ширина 1440 / 820 / 600 / 375 px,
отправка пустой формы (ошибка), отправка примера
`examples/ticket.example.txt`, работа без JS (отключить JS в браузере).

## Задача 1. Токены и типографика (фаза 0)

**Файлы:** `static/styles.css`, оба шаблона.

- Вверху `styles.css` — слой токенов: палитра (ink, muted, paper, panel, line,
  accent, accent-strong), семантика (`--success`, `--warning`, `--danger`,
  `--info`), шкалы отступов (4–48), радиусов (8–24), две тени.
- Все hex-цвета в компонентах заменить на токены; тёмная тема — только
  переопределение значений токенов. Сейчас цвета статусов/алертов дублируются
  в ~15 местах (`.status-*`, `.alert-*`, `.copy-link.*`, dark-блок внизу).
- Типографика: убрать шрифты мельче 11px, база 14px; заголовки — системный
  стек вместо Georgia (или Georgia только для h1); шкала на `clamp()`.
- `<script src="…/app.js"></script>` → добавить `defer` в обоих шаблонах.

**Готово, когда:** смена любого цвета правится в одном месте; визуально
интерфейс почти не изменился; `grep -n '#[0-9a-fA-F]\{6\}' static/styles.css`
показывает hex только в блоке токенов; чек-лист пройден.

## Задача 2. Мгновенный отклик (фаза 1)

**Файлы:** `static/app.js`, `static/favicon.svg` (новый), оба шаблона.

- Состояние загрузки кнопок всех форм (`/analyze`, `/secondary`, `/batch`):
  текст «Разбираем заявку…» / «Обрабатываем таблицу…», `aria-busy="true"`,
  блокировка повторного сабмита.
- `Ctrl/Cmd+Enter` в textarea заявки = отправка формы.
- После ответа сервера — автоскролл к `#result` / `#secondary-result`
  (в `app.js` по `DOMContentLoaded`, якоря в action форм уже есть).
- Ошибка валидации: прокрутка к alert-блоку (он рендерится над формой).
- Черновик текста заявки в `sessionStorage` (ключ `l2tool-draft`, восстановление
  после перезагрузки с ненавязчивой подсказкой; не делать для настроек).
- Favicon: `static/favicon.svg` (зелёная плашка «L2» в стиле `.brand-mark`),
  `<link rel="icon" href="…" type="image/svg+xml">` в оба шаблона.

**Готово, когда:** каждое действие даёт отклик < 100 мс; с отключённым JS
всё работает как сейчас; фавикон виден на вкладке в обеих темах.

## Задача 3. Структура страниц (фаза 2)

**Файлы:** `templates/index.html`, `templates/settings.html`, `static/styles.css`, `webapp.py` (контекст).

- Hero: когда есть результат, шапка сжимается до одной строки (класс на
  `body`/`main` рендерится серверно при `result`).
- Убрать дублирование уточнения времени: в блоке правок оставить только
  ручное поле, календарь — только в основной форме.
- Результаты: кнопка «Скопировать все ссылки» (все сервисы результата);
  `<details>` «Показать URL» в каждой строке ссылки; инлайн-SVG иконки
  платформ (Grafana / OpenSearch) в заголовках карточек.
- История: вместо `номер · количество` выводить списком даты и пути архивов
  (данные уже есть в `result.history` — словарь номер → пути).
- Настройки: карточки блоков свернуть в `<details>` (шапка: платформа,
  название, стратегия, окно; раскрытие — форма); «Удалить блок» — в общий
  ряд действий, убрать абсолютное позиционирование.

**Готово, когда:** страница настроек с 10+ блоками читается без прокрутки
каждой карточки; все ссылки результата копируются одним действием;
тесты `tests/test_webapp.py` зелёные (обновить, если меняется разметка).

## Задача 4. Отправка без перезагрузки (фаза 3)

**Файлы:** `static/app.js`, `webapp.py`, `templates/index.html`, `tests/test_webapp.py`.

- `app.js` перехватывает submit `/analyze` и `/secondary`, отправляет `fetch`,
  ответ (фрагмент HTML) вставляет в зону результатов без перезагрузки.
- `webapp.py`: при `headers['X-Requested-With']` (или query-параметром)
  возвращать только блок результатов тем же шаблоном (вынести его в Jinja
  include/macros), иначе — полную страницу, как сейчас. CSRF — как обычно,
  из формы.
- Скелеттон зоны результата на время запроса; анимация появления блоков
  (transform/opacity, отключать при `prefers-reduced-motion`).

**Готово, когда:** текст заявки и позиция скролла не сбрасываются при
повторных правках; без JS — обычный POST; добавлены тесты частичного
ответа (статус, состав фрагмента, CSRF-отказ для X-Requested-With без токена).

## Задача 5. Доступность и печать (фаза 4)

**Файлы:** `static/styles.css`, оба шаблона, `static/app.js`.

- Skip-link «Перейти к форме» (первый элемент body, видим при фокусе).
- `:focus-visible` кольца для кнопок, ссылок, чекбоксов в обеих темах.
- `aria-live="polite"` на зоне результатов и сообщениях копирования.
- `@media print`: только блок результатов — поля, сервисы, плоский список
  URL, без навигации и форм.
- `<meta name="description">`, согласованные `<title>` страниц.
- Аудит контраста обеих тем (WCAG AA для текста ≥ 12px), поправить токены.

**Готово, когда:** Lighthouse a11y ≥ 95 в обеих темах; печать результата
читаема одним листом; навигация с клавиатуры по Tab очевидна.
