# Задачи: локальный справочник кодов с подсказками в интерфейсе

Самодостаточный план для работы в отдельных чатах. Ветка:
`feature/local-reference` (создаётся от `dev`).

Цель — инструмент читает локальный (не попадающий в Git) справочник
«код → расшифровка» и показывает подсказки прямо в результатах диагностики:
если в заявке или полях правок встречается код, рядом появляется его
расшифровка. Состав справочника зависит от окружения пользователя, поэтому
реальные данные в репозиторий не попадают никогда — коммитится только
пустой шаблон.

## Как работать с задачей (для нового чата)

1. Переключиться: `git checkout dev && git checkout -b feature/local-reference`.
2. Прочитать: эту задачу, разделы «Контекст» и «Ограничения», затем файлы
   из списка задачи.
3. Сделать задачу целиком, прогнать проверки (см. ниже), коммит, push,
   PR в `dev`.

## Контекст: что уже есть

- `webapp.py` — FastAPI-приложение, только localhost; рендер результатов
  через `templates/_results.html` (фрагмент для XHR) и полную страницу
  `templates/index.html`.
- `core/dynamic_sources.py` — образец работы с локальным JSON: чтение,
  атомарная запись с правами 0600, валидация, лимит размера. Схему
  хранения нового справочника делать по той же модели.
- `config.toml`, `diagnostic_sources.json` — существующие локальные файлы,
  уже игнорируемые Git; справочник становится третьим таким файлом.
- Парсер заявки: `core/parser.py` + `core/ticket_fields.py`; результат
  разбора и правки полей приходят в шаблоны.

## Ограничения (нарушать нельзя)

- Реальное содержимое справочника — только в локальном файле, Git
  игнорирует его (добавить в `.gitignore`); в репозитории — шаблон
  `reference_codes.example.json` без данных и документация формата.
- Права 0600, атомарная запись, лимит размера файла (например 256 КБ).
- CSP `script-src 'self'; style-src 'self'` — без инлайн-скриптов;
  расшифровка рендерится на сервере, поэтому всё работает и без JS.
- Никаких обращений наружу: файл читается с диска при запросе.

## Задача 1. Хранилище справочника

- `core/reference_codes.py`: чтение `reference_codes.json` из корня
  (формат: `{"группа": {"код": "текст"}}`, группы — произвольные строки,
  например названия внутренних справочников). Нет файла — пустой
  справочник, приложение работает как раньше.
- Валидация: строки не длиннее 500 символов, коды — строки до 16 символов,
  не более 1000 записей. Ошибки формата не валят приложение — справочник
  считается пустым, ошибка показывается один раз в лог.
- `.gitignore`: добавить `reference_codes.json` (кроме example-файла —
  паттерн по аналогии с `examples/*.txt`).
- `reference_codes.example.json` в репозитории: пустые группы и комментарий
  формата в README-разделе.

**Готово, когда:** приложение стартует с файлом, без файла и с битым
файлом; тесты на все три случая.

## Задача 2. Расшифровка кодов в результатах

- Детекция: серверный поиск в тексте заявки и значениях полей правок по
  шаблону вида `(?i)\b(группа)\s*[:=]?\s*([0-9]{1,3})\b`, где «группа» —
  ключ из справочника. Находки не меняют разбор заявки, только добавляются
  в контекст шаблона.
- Отображение: блок «Расшифровка кодов» в результатах (`_results.html` и
  `index.html`): строка «Decision 10 — <текст>». Без совпадений блок не
  показывается.
- Дубликаты схлопываются, порядок — как в тексте.

**Готово, когда:** заявка с кодами показывает расшифровки без JS; заявка
без кодов не показывает блок; тесты на подстановку и дубликаты.

## Задача 3. Страница справочника и импорт/экспорт

- Роут `/reference`: таблица «группа · код · расшифровка», работает без JS.
- Импорт/экспорт JSON-файла на той же странице по образцу
  `/settings/import` и `/settings/export` (проверка целиком, затем замена;
  экспорт — текущий файл).
- Ссылка на страницу из настроек.

**Готово, когда:** справочник можно заполнить через сайт и файлом; тесты
на импорт-экспорт и лимиты.
