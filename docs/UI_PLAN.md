# План модернизации веб-интерфейса l2tool

Статус: **реализовано** (фазы 0–4, сентябрь 2026), после чего композиция
переработана в «рабочую консоль»: убран hero и промо-карточки, страница
начинается с формы, панели плоские и плотные. Слой токенов, fetch-отправка
без перезагрузки, черновики, доступность и печать сохранены.
База — `templates/index.html`, `templates/settings.html`,
`templates/_results.html` (фрагмент результатов для XHR), `static/styles.css`,
`static/app.js`.

## Проход 2: «спокойная инженерная консоль» (сентябрь 2026)

Полный редизайн первого прохода по направлению UI-агента: нейтральная
графитовая база вместо «бумажной» зелёно-лаймовой, плоские поверхности
с 1px-рамками вместо вложенных плашек, один сдержанный зелёный акцент,
единая система кнопок и бейджей, моно-шрифт для номеров/UUID/URL/времён.

Токен-слой (`static/styles.css`):

- Новые `:root`/`:root[data-theme="dark"]`: `--bg/--surface/--surface-muted/
  --surface-hover`, `--border/--border-strong/--border-soft`, `--text/
  --text-muted/--text-faint`, `--accent(-hover/-contrast/-subtle-bg/-subtle-fg)`,
  статусные тройки success/warning/danger/info, `--control-*`, `--radius-xs..lg`,
  `--shadow-sm/md/focus`, `--control-h`, `--skeleton-bg`. Продуктовые
  `--product-*` не тронуты (синхронизация с `core/products.py`).
- Удалены: `--page-glow` (фон `body` плоский, без радиального градиента),
  `--accent-bright/-hover` (лаймовая пара), группа `--on-accent-*`,
  `--quiet-button`, `--text-2xs`, `--focus-ring`. Возвращены
  `--radius-md/--radius-lg` — чинит нулевой радиус у `.preview-link`,
  `.product-row`, `.backup-row`.
- Типографика: минимум 12px (11px убраны), веса только 400/500/600/700,
  межстрочные 1.5/1.3/1.6, заголовки ≥16px с letter-spacing -0.01em,
  eyebrow 12px/600/uppercase/0.06em/`--text-muted`, tabular-nums для времён
  и счётчиков. `Inter` убран из `--font-sans` (не грузится по CSP), стек
  только системный; расширен `--font-mono`.
- Компонентный слой без единого hex/rgba (производные — `color-mix` от
  токенов); hex допустимы только в токен-блоках и `@media print`.

Компоненты:

- Кнопки: одна система, `--radius-sm`, вес 600; primary (accent) /
  secondary (прозрачная + рамка, hover фон `--surface-hover` + рамка accent) /
  danger (outline → hover-заливка `--danger-strong`) / ghost (`.quiet-button`,
  `.copy-link`, `.download-config`, `.button-link` — без заливки, hover
  `--surface-hover`). Убран `translateY(1px)` на `:active`. Размеры: CTA
  формы заявки 40px, стандарт 36px, микро 28–30px. `disabled` —
  `--control-disabled-*`, `button[aria-busy]` — opacity 0.75 + progress.
- Поля: высота `--control-h` (36px, форма заявки 40px), нативный select без
  `appearance:none`, чекбоксы 16px с `accent-color`, readonly/disabled —
  disabled-токены, `::placeholder` через `--text-faint`.
- Панели: `1px var(--border)` + `--radius-md` + `--surface`, без теней;
  тень только у sticky-элементов (topbar). `service-card` — вложенность
  фоном `--surface-muted`. Бейджи статусов — pill из статусных токенов,
  нейтральные (`call-badge`, `timezone-badge`, `source-status`) —
  `--surface-hover`/`--text-muted`, `--radius-xs`. Скелетоны — `--skeleton-bg`.

## 1. Жёсткие ограничения (менять нельзя)

Интерфейс живёт под строгой политикой безопасности `webapp.py`, поэтому любой
апдейт обязан сохранять:

- **CSP `script-src 'self'; style-src 'self'`** — никаких внешних шрифтов
  (Google Fonts), CDN, инлайн-скриптов и инлайн-стилей. Только системные
  шрифты и файлы из `/static`.
- **Работа без JavaScript.** Все формы — обычные POST; JS только улучшает.
  Любая новая фича деградирует до рабочей версии без скриптов.
- **Только localhost**, никаких внешних запросов из браузера, кроме переходов
  по сформированным ссылкам самим пользователем.
- `Cache-Control: no-store` — кэшбастинг через `?v=` в ссылках на стили
  продолжает делать вручную при каждом изменении CSS/JS.

## 3. Направление дизайна

Сохраняем узнаваемую «зелёную редакционную» идентичность, но наводим
инженерный порядок:

- **Токены вместо hex-ов.** Один слой CSS-переменных: палитра (ink, muted,
  surface, line, accent, accent-strong), семантика (`--success`, `--warning`,
  `--danger`, `--info`), шкалы отступов (4/8/12/16/24/32/48), радиусов
  (8/12/18/24) и теней (2 уровня). Все компоненты используют только токены;
  тёмная тема переопределяет токены, а не компоненты.
- **Типографика.** Заголовки — системный гротеск (тот же стек, что и текст,
  вес 650–700, tight letter-spacing); серифную Georgia оставляем только
  крупному h1 на главной или убираем совсем. Базовый текст 14px, подписи
  12px, минимум 10px нигде не используется.
- **Плотность.** Рабочая зона (textarea + продукт + окно) — на первом экране;
  hero сжимается до одной строки-подзаголовка после первого результата.
- **Отклик.** Кнопки получают состояния загрузки, переходы 120–160ms,
  вся анимация гасится через `prefers-reduced-motion`.

## 4. Фазы

Каждая фаза самостоятельна и деплоится отдельно. Оценки — относительно
текущего объёма фронтенда (~850 строк HTML+CSS+JS).

### Фаза 0 — фундамент: токены и типографика (S)

- `static/styles.css`: верх файла превращается в слой токенов (light + dark
  в одном `:root`-блоке с переопределениями), ниже — компоненты, использующие
  только токены.
- Заменить все дублирующиеся hex-цвета статусов/предупреждений на семантические
  токены; dark-тема сводится к замене значений токенов.
- Типографическая шкала на `clamp()`; убрать 9–10px подписи.
- `<script … defer>` в обоих шаблонах.
- Критерий приёмки: пиксельных отличий от текущей версии почти нет, но смена
  палитры/тёмной темы правится в одном месте; `ruff`/`pytest` не затронуты.

### Фаза 1 — мгновенный отклик без смены стека (M)

Без fetch, чистый HTML+JS поверх существующих форм:

- Состояние загрузки кнопок: текст «Разбираем заявку…», `aria-busy`,
  блокировка повторного сабмита (`app.js` перехватывает `submit`, ставит
  класс; работает и для `/batch` — «Обрабатываем таблицу…»).
- Автоскролл к `#result`/`#secondary-result` после ответа (маленький инлайн
  скрипт нельзя — CSP; вместо него `app.js` по `DOMContentLoaded` скроллит,
  если результат существует).
- Ошибка валидации дополнительно показывается у формы (скролл к alert).
- `Ctrl/Cmd+Enter` в textarea = отправка.
- Черновик текста заявки в `sessionStorage` (только на время вкладки,
  с кнопкой «восстановить» после перезагрузки; в настройках не трогаем).
- Favicon: инлайн SVG-файл `/static/favicon.svg` (зелёная плашка «L2»),
  `<link rel="icon">` в обоих шаблонах — CSP `img-src 'self'` разрешает.
- Критерий приёмки: любое действие даёт отклик < 100ms; без JS всё работает
  как сейчас.

### Фаза 2 — структура и содержание страниц (M)

- **Главная.** Hero сжимается после первого анализа (CSS-класс на `body`
  рендерится серверно, если есть результат). Дубли уточнения времени:
  picker в основной форме остаётся, из блока правок убирается второй
  picker, остаётся ручное поле.
- **Результаты.** В карточку сервиса — платформенная иконка (инлайн SVG
  в HTML, это разрешено), кнопка «Скопировать все ссылки», expandable
  «показать URL» через `<details>` (без JS).
- **Настройки.** Карточки блоков сворачиваются в `<details open>`: шапка
  (платформа, название, стратегия подстановки, окно) + «Изменить»;
  форма раскрывается по клику. Удаление — в строку действий рядом с
  «Сохранить», не абсолютным позиционированием.
- Критерий приёмки: настройки из 10+ блоков читаются без скролла каждой
  карточки; из результата можно забрать все ссылки одним действием.

### Фаза 3 — прогрессивное улучшение отправки (L)

- Отправка `/analyze` и `/secondary` через `fetch` без перезагрузки:
  `app.js` сериализует форму, `webapp.py` дополнительно отдаёт результат
  частичным шаблоном (Jinja-include тот же макрос) или фрагментом HTML,
  который вставляется на место. Фолбэк: без JS — обычный POST, как сейчас.
  CSRF-токен передаётся в теле как обычно.
- Skeleton-заглушка зоны результата на время запроса.
- Анимация появления блоков результата (только transform/opacity,
  отключается при `prefers-reduced-motion`).
- Критерий приёмки: текст заявки и скролл не сбрасываются при повторных
  правках; поведение без JS идентично текущему; все тесты
  `tests/test_webapp.py` зелёные + добавлены тесты частичного ответа.

### Фаза 4 — доступность и полировка (S–M)

- Skip-link «к форме», видимые `:focus-visible` кольца на всех интерактивных
  элементах, `aria-live="polite"` на зоне результатов.
- Аудит контраста обоих тем (целевой WCAG AA для текста ≥ 12px).
- Стили печати `@media print`: только блок результатов — поля, сервисы,
  плоский список URL.
- Мелочи: `<meta name="description">`, согласованные `title` страниц.
- Критерий приёмки: Lighthouse a11y ≥ 95 в обеих темах; печать результата
  читаема одним листом.

## 5. Что сознательно не делаем

- Не подключаем внешние шрифты, иконкопаки и CDN (CSP).
- Не вводим сборщик (webpack/vite) и фреймворки — фронтенд остаётся
  vanilla и читаемым.
- Не делаем SPA и клиентский роутинг; сервер остаётся источником истины.
- Не добавляем телеметрию и внешние запросы.
- Не храним черновики заявок на диске — только `sessionStorage` вкладки.

## 6. Порядок и трекинг

Рекомендуемый порядок: 0 → 1 → 2 → 4 → 3 (доступность дешевле делать до
перехода на fetch). Каждая фаза — отдельный PR в `dev` с пометкой фазы
(`ui: phase N — …`), скриншотами светлой и тёмной темы и прогоном
`python -m pytest -q` + `python -m ruff check .`.
