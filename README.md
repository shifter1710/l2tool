# l2tool

Вставляете текст заявки — получаете нормализованные номера, дату, время,
регион и готовые ссылки на Grafana и OpenSearch. Работает веб-интерфейс и
CLI. Всё выполняется на вашем компьютере: l2tool сам никуда не ходит по
API, ссылки открываются в браузере.

Пошаговые сценарии — в [docs/USAGE.md](docs/USAGE.md), устройство сервиса —
в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), план развития интерфейса —
в [docs/UI_PLAN.md](docs/UI_PLAN.md).

## Запуск

Скачайте исходники со страницы
[Releases](https://github.com/shifter1710/l2tool/releases) (или склонируйте
репозиторий) и запустите:

| Система | Команда |
| --- | --- |
| Linux / macOS | `./start.sh` |
| Windows | `start.bat` (двойной клик или из терминала) |

Нужен только Python 3.10+. При первом запуске скрипт сам создаст
окружение `.venv`, поставит зависимости и откроет браузер на
`http://127.0.0.1:8765`; повторные запуски стартуют мгновенно.

Флаги `webapp.py` передаются скрипту напрямую:

```bash
./start.sh --port 9000      # другой порт (по умолчанию 8765)
./start.sh --no-browser     # не открывать браузер
```

Без скрипта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python webapp.py
```

Единственное внешнее требование — доступ к Grafana и OpenSearch вашего
окружения: их адреса настраиваются на следующем шаге.

## Первый разбор заявки

1. Вставьте текст заявки в форму, выберите продукт и нажмите
   **«Разобрать заявку»** (или Ctrl+Enter в поле заявки).
2. Проверьте распознанные поля над ссылками: номер А и Б (с хешем для
   поиска в логах BFF), дату и время, регион с UTC-смещением.
   Распозналось неверно — заполните нужное поле в блоке «Если что-то
   распознано неверно» под результатами и нажмите «Пересобрать результат»;
   исходный текст заявки не меняется.
3. Открывайте ссылки или копируйте их одной кнопкой. Каждая помечена, по
   какому значению построена (номер клиента, А, Б или UUID).

Дальше по необходимости:

- **Второй этап по UUID** — когда в логах найден UUID звонка, отдельная
  форма прогоняет блоки уровня «Поиск по UUID».
- **История звонков из баланса** — вставьте выгрузку детализации: ссылки
  построятся по каждому звонку, переадресации сгруппируются.
- **Потерянные звонки** — загрузите таблицу XLSX/CSV, скачайте готовый
  XLSX со ссылками.

Если в заявке нет даты и времени, ссылки всё равно построятся — диапазон
возьмётся из настроек блока, а в предупреждениях отметится, что время
не найдено.

## Подключение своих дашбордов

### Способ 1 — блоки в интерфейсе (рекомендуемый)

Откройте **«Настройки источников» → «Добавить блок»**:

1. Вставьте в поле «Пример готовой ссылки» любую рабочую ссылку Grafana
   или OpenSearch, где вместо номера клиента стоит тестовый номер (или
   UUID). l2tool сам определит платформу и способ подстановки.
2. Нажмите **«Проверить ссылку»** — увидите готовый URL с подстановкой
   и текущим временем. Всё выглядит правильно — сохраняйте.
3. Блок сразу участвует в диагностике. Не нужен — выключите тумблером,
   порядок ссылок задаётся кнопками «Выше/Ниже».
4. Хотите фиксированный диапазон вместо окна вокруг звонка — заполните
   оба поля «Диапазон от / до» в формате Grafana (`now-5d` … `now`).

Продукты (включая свои) и их блоки редактируются там же. Ключи встроенных
продуктов (`recording`, `secretary`, `calls`, `noise`, `assistant`)
неизменны — на них ссылается CLI.

### Способ 2 — config.toml

Подходит, если настраиваете в первую очередь CLI:

```bash
cp config.example.toml config.toml
```

Откройте нужный дашборд Grafana или представление OpenSearch Discover и
скопируйте URL в соответствующую секцию:

```toml
[services.zapis]
url = "https://grafana.example.local/d/...?..."

[services.bff]
url = "https://dashboards.example.local/app/data-explorer/discover#?..."
```

- Grafana: статические параметры ссылки (`orgId`, окружение, кластер)
  сохраняются, значения из заявки подставляются на место примера.
- OpenSearch: из ссылки извлекается `indexPattern`, запрос и диапазон
  заменяются данными заявки.
- Окно каждой ссылки задаётся `minutes_before` / `minutes_after`
  (по умолчанию 2 минуты до и 90 после звонка).
- Для `myconnect_call` отдельный URL не нужен — используется
  `[services.myconnect]`.

`config.toml` игнорируется Git; держите в нём только локальные адреса.
Кнопка **«Перенести сервисы из config.toml»** на странице настроек
разом превратит заполненные секции `[services.*]` в динамические блоки.

Значения по умолчанию для форм и CLI переопределяются секциями
`[defaults]`, `[gtool]`, `[call_history]` — все ключи перечислены в
`config.example.toml`. Там же секция `[features]` для экспериментальных
функций: ранбук «куда смотреть» включается явно (`runbook = true`) и по
умолчанию выключен; его данные в `runbook.json` и бандле конфигураций
сохраняются независимо от тогла.

## Перенос настройки на другой компьютер

На странице настроек, раздел «Данные»:

- **«Все конфиги сразу»** — один JSON-файл со всем: блоки с номерами
  Секретаря, справочник кодов, ранбук и `config.toml`. Загрузка на другой
  машине переносит настройку целиком; блоки добавляются к существующим,
  дубликаты пропускаются, недостающие продукты создаются.
- Каждое хранилище переносится и по отдельности: блоки —
  `diagnostic_sources.json`, справочник — страница `/reference`, ранбук —
  панель ранбука, `config.toml` — строка «Статический профиль отдельно».

Секреты фильтруются автоматически: ключи `token` / `password` / `api_key`…,
параметры вида `?token=…` и логин-пароль внутри ссылки отклоняются при
импорте, а `config.toml` с секретами не включается в выгрузку. Ссылки
допускаются только http(s).

Перед каждым изменением настроек автоматически создаётся копия в `backups/`
(последние 20) — случайно удалённый блок можно вернуть кнопкой
«Откатиться» в списке копий.

## Частые вопросы

**Порт 8765 занят.**
Запустите на другом: `./start.sh --port 9000`.

**«Форма устарела. Обновите страницу».**
Сервер перезапускался, и токен формы сбросился — нажмите F5 и отправьте
заявку ещё раз.

**Импорт конфигурации ругается на токен.**
В ссылке или config.toml найден ключ доступа (`token`, `password`,
`api_key`, `?access_token=…`, `user:pass@host`). Уберите его — l2tool
сознательно не даёт разносить секреты файлами конфигураций.

**В заявке нет времени звонка.**
Ссылки построятся с диапазоном из настроек блока (now-выражение или период
из ссылки-примера); в предупреждениях будет отметка «время не найдено».

**Браузер не открылся сам.**
Откройте `http://127.0.0.1:8765` вручную или запускайте с `--no-browser`.

**Распозналось не то поле.**
Заполните нужное поле в блоке «Если что-то распознано неверно» под
результатами и нажмите «Пересобрать результат» — правка попадёт в разбор
без изменения исходного текста заявки.

**Как посмотреть, что уже разбиралось?**
В веб-форме включите галочку «Сохранить успешный результат в локальную
историю» — успешные заявки лягут в `history/`, и при следующем разборе с
тем же номером l2tool покажет найденное ранее. В CLI история пишется по
умолчанию (только успешные разборы); `--no-history` отключает.

**Удалил блок случайно.**
Настройки → список копий в `backups/` → «Откатиться». Откат тоже
копируется, поэтому его можно отменить.

## Где хранятся данные

| Путь | Что лежит | Создаётся |
| --- | --- | --- |
| `config.toml` | адреса сервисов и значения по умолчанию | вами |
| `diagnostic_sources.json` | продукты и диагностические блоки | редактором настроек |
| `backups/` | копии настроек (последние 20) | автоматически |
| `reference_codes.json` | справочник кодов | страницей `/reference` |
| `tickets/` | тексты заявок для CLI | вами |
| `history/`, `history/index.json` | YAML-архивы успешных разборов | галочкой «сохранять» / CLI |
| `*.parsed.json` | последний разбор заявки (JSON) | при каждом запуске CLI |
| `*.cleaned.xlsx` | очищенная таблица потерянных звонков | после пакетной обработки |

Все пути игнорируются Git. Ничего не отправляется во внешние сервисы:
страницы не кэшируются, сервер слушает только 127.0.0.1, временные файлы
удаляются сразу после скачивания. Полный список с пояснениями — в
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#10-хранилища-и-локальные-данные).

`--dry-run` в CLI не записывает ни историю, ни диагностические данные
парсера; `--no-history` отключает только историю.

## Справочник кодов

Расшифровки внутренних кодов («Decision 10 — …») показываются прямо в
результатах, если код из заявки найден в справочнике. Заполнить — на
странице `/reference` (импорт/экспорт JSON) или создав `reference_codes.json`
в корне:

```json
{
  "Decision": { "10": "Абонент вне зоны покрытия" },
  "Reason": { "42": "Перегрузка MGW" }
}
```

Формат — «группа → {код → расшифровка}». Код распознаётся по шаблону
«Группа 10», «Группа: 10» или «Группа=10». Лимиты: группы до 80 символов,
коды до 16, расшифровки до 500, всего до 1000 записей и 256 КБ.

## CLI

Стандартный сценарий — заявка в `tickets/current.txt`, затем:

```bash
.venv/bin/python gtool.py                     # разбор + открытие ссылок по умолчанию
.venv/bin/python gtool.py --open zapis,bff    # конкретные сервисы
.venv/bin/python gtool.py --product calls     # профиль продукта
```

| Флаг | Что делает |
| --- | --- |
| `--file путь` | файл заявки (по умолчанию `tickets/current.txt`) |
| `--product ключ` | профиль продукта вместо `--open` |
| `--open список` | сервисы/блоки: имена из реестра, id или названия блоков |
| `--window минуты` | окно вокруг звонка (по умолчанию 60) |
| `--call-uuid UUID` | вторичная диагностика записи по UUID |
| `--export-case файл` | записать разбор в JSON |
| `--no-history` | не сохранять архив истории |
| `--dry-run` | ничего не записывать на диск |

Сервисы по умолчанию: `zapis` — логи звонков (Grafana find-call-in-logs),
`sip_stack` и `bff` — логи SIP/BFF в OpenSearch, `secretary` и `noise` —
Loki по номеру, `myconnect` — «profile not found», `myconnect_call` —
присоединённый звонок. Полная таблица с цепочкой записи — в
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#8-реестр-сервисов-и-модули).

Пошаговые сценарии CLI (экспорт JSON, UUID, потерянные звонки, история из
баланса) — в [docs/USAGE.md](docs/USAGE.md).

## Разработка

```bash
python3 -m pip install -r requirements-dev.txt
python -m pytest -q        # тесты полностью офлайн
python -m ruff check .
```

CI гоняет матрицу Python 3.10–3.12. При изменении архитектуры обновляйте
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md); выполненные задачи — в архиве
[docs/tasks/done/](docs/tasks/done), правила ветвления и синтетические
данные — в [CONTRIBUTING.md](CONTRIBUTING.md).
