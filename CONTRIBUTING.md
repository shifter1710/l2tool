# Правила работы с ветками

## `dev`

- Основная ветка для текущей разработки.
- Новые функции, исправления и промежуточные изменения сначала попадают сюда.
- Ветка может содержать работу, которая ещё не готова к выпуску, но каждый
  отправляемый коммит должен оставаться понятным и не содержать локальных
  конфигов, заявок, выгрузок или секретов.

## `main`

- Содержит только целостные и законченные изменения.
- Перед слиянием из `dev` должен проходить полный набор тестов.
- Изменение должно быть проверено в рабочем сценарии и иметь необходимую
  документацию.
- Предпочтительный способ обновления — pull request из `dev` в `main`.
- Незавершённую работу напрямую в `main` не отправляем.

## Выпуск изменения

1. Разработать и проверить изменение в `dev`.
2. Запустить `python -m pytest -q` и `python -m ruff check .`
   (зависимости — из `requirements-dev.txt`, как в CI).
3. Убедиться, что локальные данные и секреты не попали в Git.
4. Обновить затронутую документацию: `README.md`, при изменении архитектуры —
   `docs/ARCHITECTURE.md`, при изменении фронтенда — `docs/UI_PLAN.md`.
5. Создать pull request `dev` → `main`.
6. После проверки слить pull request в `main`.

Срочное исправление можно выполнить отдельной веткой от `main`, после чего его
нужно также перенести обратно в `dev`.
